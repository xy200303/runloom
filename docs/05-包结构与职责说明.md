# 包结构与职责说明

## Monorepo 布局

```text
runloom/
  package.json
  tsconfig.base.json
  docs/
  packages/
    runloom-agent/
      package.json
      README.md
      src/
      examples/
      test/
    runloom-tui/
      package.json
      README.md
      src/
      examples/
      test/
    runloom-web/        后期创建，Vue 3 + TypeScript + Vite
      package.json
      README.md
      src/
      examples/
      test/
```

根项目负责 workspace、统一脚本、CI、版本和发布。每个 package 独立负责自己的 public API、README、examples、exports、types 和测试。

## 依赖方向

```text
runloom-tui  -> runloom-agent
runloom-web  -> runloom-agent
third-party  -> runloom-agent / runloom-tui / runloom-web
```

禁止方向：

- `runloom-agent` 不依赖 `runloom-tui` 或 `runloom-web`。
- `runloom-tui` 不依赖 `runloom-web`。
- `runloom-web` 不依赖 `runloom-tui`。
- 任何包都不能 import 其他包的 `src/internal`。

## runloom-agent

`runloom-agent` 是核心 headless runtime，也是最重要的 npm 包。

职责：

- 动态 agent loop。
- pi-agent 集成。
- 模型协议统一。
- 工具抽象、注册、执行、权限和 approval。
- session、store、message、transcript 和事件流。
- todo 管理。
- context 和 message 管理。
- redaction、安全护栏、可观测性和错误处理。
- Skills、MCP、A2A、external agents。
- 本地成长层、自我演化、Tool Forge、Skill Forge、eval gate。
- 面向 TUI/Web/第三方应用的稳定 public API。

建议内部目录：

```text
packages/runloom-agent/src/
  index.ts
  runtime/
  providers/
  tools/
  skills/
  mcp/
  a2a/
  external-agents/
  memory/
  growth/
  evolution/
  evals/
  sessions/
  approvals/
  events/
  security/
  observability/
  prompts/
  internal/
```

`index.ts` 只导出稳定 public API。`internal/` 下内容不进入 exports。

## runloom-tui

`runloom-tui` 是终端界面包，可作为 CLI 使用，也可被开发者嵌入自己的终端应用。

职责：

- CLI bin：`runloom`。
- 输入框、命令、快捷键。
- transcript 展示。
- todo 展示。
- tool activity 展示。
- approval 交互。
- session 列表和切换。
- Skills/MCP/A2A/external agent 状态展示。
- 本地成长状态和 proposal 确认入口。

不负责：

- 不实现 agent loop。
- 不直接调用供应商模型 API。
- 不直接执行工具。
- 不保存业务状态，只通过 agent store 和 public API 读写。

建议目录：

```text
packages/runloom-tui/src/
  index.ts
  bin/
  app/
  components/
  commands/
  keymap/
  renderers/
  themes/
```

## runloom-web

`runloom-web` 是后期实现的 Web server/API/SSE/WebSocket 和 Vue 组件层包，可独立启动，也可挂载到已有服务。首期不实现和发布该包，只保留设计文档与包边界。

职责：

- 使用 Vue 3 + TypeScript + Vite 实现前端组件和工作台。
- 独立 Web server。
- 可嵌入 HTTP handler/router。
- session API。
- submit API。
- event stream API。
- approvals API。
- todo API。
- skills/mcp/a2a/memory/evolution 状态 API。
- Web transcript、todo、tool activity、approval dialog、session list、proposal manager 等组件。

不负责：

- 不实现 agent loop。
- 不绕过 `runloom-agent` 调工具。
- 不直接读写 `~/.runloom` 内部文件，除非通过 agent public API。

建议目录：

```text
packages/runloom-web/src/
  index.ts
  server/
  api/
  sse/
  websocket/
  components/
  hooks/
  client/
  styles/
```

## 跨包类型共享

跨包共享类型应从 `runloom-agent` public API 导出。例如：

- `RunloomEvent`
- `RunloomAgent`
- `RunloomSession`
- `RunloomTodoItem`
- `ApprovalRequest`
- `ExternalAgentStatus`
- `SkillManifest`

`runloom-tui` 和 `runloom-web` 不维护自己的事件类型副本。若 UI 需要额外视图模型，应在包内转换，并保持输入类型来自 `runloom-agent`。

## Public API 稳定性

每个已发布包必须配置明确 exports：

```json
{
  "type": "module",
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "import": "./dist/index.js"
    }
  }
}
```

原则：

- 默认只导出根入口。
- 需要可选子路径时必须明确，如 `runloom-web/server`、`runloom-web/components`。
- 不开放 `dist/internal/*`。
- public API 变更必须记录 changelog，并遵守 semver。

## README 与 examples

每个已发布包必须包含：

- 安装方式。
- 最小示例。
- public API 列表。
- 配置说明。
- 常见错误。
- 版本兼容说明。

最小示例：

- `runloom-agent/examples/minimal.ts`。
- `runloom-tui/examples/embedded.ts`。
- `runloom-web/examples/standalone-server.ts`，后期 Web 实现时补齐。
- `runloom-web/examples/mount-existing-server.ts`，后期 Web 实现时补齐。

## 禁止实现 DAG Workflow

Runloom 明确不创建以下模块：

- `workflow/`
- `dag/`
- `WorkflowPatch`
- `WorkflowVersionGraph`
- 显式 workflow runtime。

可以有 task strategy、todo、plan、run step 和 event replay，但它们服务于动态 agent loop，不构成 workflow graph。
