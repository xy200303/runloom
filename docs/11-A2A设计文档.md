# A2A 设计文档

## 定位

A2A 用于让 Runloom 与其他 agent 互操作。Runloom 可以作为主 agent 委托任务给外部 specialist agent，也可以把自己的能力暴露为本地 agent service，供其他 agent 调用。

A2A 能力由 `runloom-agent` 实现。`runloom-tui` 和 `runloom-web` 只负责展示 discovery、delegation、status 和 result。

当前首期已落地最小 public surface：`runloom-agent` 暴露 A2A peer/capability summary、peer registration、delegation request/result 类型，以及
`registerA2APeer(...)`、`listA2APeers()`、`delegateA2APeer(...)`；注册 peer 时写入 `a2a.peer.discovered` 事件。当前 delegation 先支持 host 注册的本地 delegate handler，并接入 `a2a.delegation` approval policy、`a2a.*` events 和 audit record。真实协议 client/server、跨进程 transport 和完整 result exchange 仍按本文后续设计推进。

## 能力范围

首期 A2A 设计包括：

- agent discovery。
- capability description。
- task delegation。
- result exchange。
- status events。
- permission control。
- audit trail。

## Peer 配置

```text
~/.runloom/
  a2a/
    peers.json
```

示例：

```json
{
  "peers": {
    "local-doc-agent": {
      "endpoint": "http://127.0.0.1:43120/a2a",
      "enabled": true,
      "trust": "local",
      "permissions": {
        "delegate": "ask",
        "readWorkspace": false,
        "writeWorkspace": false
      }
    }
  }
}
```

## Discovery

Runloom 作为 client：

```text
GET /.well-known/agent.json
```

期望返回：

```json
{
  "id": "local-doc-agent",
  "name": "Local Documentation Agent",
  "version": "0.1.0",
  "capabilities": [
    {
      "name": "summarize-docs",
      "description": "Summarize project documentation",
      "inputSchema": {},
      "outputSchema": {}
    }
  ]
}
```

Runloom 作为 server 时也应暴露自己的 capability description，但默认只在本地启用。

## Delegation

委托请求：

```ts
export interface A2ADelegationRequest {
  task: string;
  workspace: string;
  sessionId?: string;
  runId?: string;
  approvalId?: string;
  capability?: string;
  constraints?: string[];
  context?: ExternalAgentContextItem[];
}

export interface A2ADelegationResult {
  status: "completed" | "failed" | "cancelled" | "waiting_approval";
  summary: string;
  approvalId?: string;
  outputText?: string;
  structuredOutput?: unknown;
  events?: RunloomEvent[];
  diagnostics?: string[];
}
```

流程：

```text
select peer
  -> validate capability
  -> permission policy
  -> approval if needed
  -> send task
  -> subscribe status events
  -> collect result
  -> validate output schema
  -> write audit
  -> append result to Runloom context
```

## Status Events

```ts
export type A2AStatusEvent =
  | { type: "task.accepted"; taskId: string }
  | { type: "task.started"; taskId: string }
  | { type: "task.progress"; taskId: string; message: string; percent?: number }
  | { type: "task.tool_activity"; taskId: string; summary: string }
  | { type: "task.waiting_approval"; taskId: string; summary: string }
  | { type: "task.completed"; taskId: string; result: unknown }
  | { type: "task.failed"; taskId: string; error: unknown }
  | { type: "task.cancelled"; taskId: string };
```

这些事件映射为 Runloom 事件：

- `a2a.peer.discovered`
- `a2a.delegated`
- `a2a.approval_requested`
- `a2a.approved`
- `a2a.event`
- `a2a.completed`
- `a2a.failed`

## Result Exchange

结果必须包含：

- summary。
- structured result。
- evidence。
- changed files summary，如果 peer 修改了文件。
- verification notes。
- limitations。

Runloom 不自动信任结果：

- schema 校验。
- 必要时二次验证。
- 文件改动进入 diff review。
- 高影响结果需要 approval。

## Runloom 作为 A2A Server

Runloom 可以暴露：

- project understanding。
- code review。
- file edit proposal。
- memory query。
- skill recommendation。
- tool execution under approval。
- eval benchmark execution。

默认安全策略：

- 只监听 localhost。
- 外部 peer 默认无写权限。
- 高影响 capability 默认 `ask`。
- 每个外部任务都有独立 run/session。

## 与 ExternalAgentAdapter 的关系

A2A 是协议级协作；ExternalAgentAdapter 是本地集成层。

- 如果对方 agent 有标准 A2A endpoint，优先走 A2A。
- 如果对方只有 CLI 或 SDK，使用 adapter。
- 两种方式都必须进入统一 permissions、approval、events、audit。

## 安全

A2A 风险：

- peer 伪造能力。
- peer 返回恶意 prompt。
- peer 请求越权资源。
- peer 诱导 Runloom 执行危险工具。
- 结果中包含 secret 或 prompt injection。

控制：

- peer 配置白名单。
- discovery 结果缓存和校验。
- trust level。
- request/response schema。
- redaction。
- prompt injection scanning。
- per-task permission sandbox。
- audit trail。

## 测试

- status event streaming。
- schema validation。
- timeout/cancel。
